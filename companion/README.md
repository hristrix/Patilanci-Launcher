# Patilanci Skin Companion

Client-only Fabric 1.21.10 mod. The launcher installs its bundled JAR after pack preparation and passes a Base64url JSON request in `-Dpatilanci.skin.request`. No server address, password, account token, or skin choice is hardcoded into the JAR. Without a request it registers no events, so premium launches remain inactive.

The request contains `player`, `server`, and a validated own-player `skin set` command. It only runs while the session name and current server address match. It waits five seconds after joining and for the server's `/skin` command tree. A server system message confirming login/registration schedules an application two seconds later, or one retry if the initial command already ran. Disconnect clears the pending attempt. It does not type keys, use the clipboard, read passwords, or claim that sending the command confirms the server applied it. SkinRestorer's own chat feedback reports the result.

Supported authentication confirmations include PatilanciAuth's “Successfully logged in” and “Registered and authenticated successfully”, plus “logged in successfully”, “successfully registered”, and “already authenticated”. Servers with different/localized confirmation messages need the matcher adapted; manual command copying is always available. A missing or disallowed `/skin` command shows a local explanation after ten seconds of waiting. No permissions are bypassed.

Build with Java 21 or later: `./gradlew build` (Windows: `.\gradlew.bat build`), from this directory. This includes `verifySkinLogic`, which checks the command schedule, matching server/player, permissions timeout, login retry, and disconnect behavior without a live server. Output: `build/libs/patilanci-skin-companion-1.0.0.jar`. Run `node update-bundle.cjs` here to copy this remapped JAR and generate its SHA-256 digest under `electron/assets`. Commit both generated artifacts with their source changes. The Node tests check bundled metadata/hash and launcher activation. Building validates the Minecraft/Fabric APIs; actual multiplayer visibility requires testing against the live server.

Shared rendering is handled separately by the official CustomSkinLoader mod, downloaded and verified by `electron/shared-skins.cjs`. It does not depend on this command companion, and it remains active for premium players so they can see Ely.by skins. The two modules do not change game authentication or server identity.
